# Phase 3 integration requests

These requests identify changes outside the Phase 3 edit allowlist. None were made here.

- **Detector evidence transport:** emit `failure_evidence` alongside the existing Kafka alert fields, containing `failure_type`, `span_id` (or a zero-based span `step`), and `supporting_text`. The critic consumer already accepts this field and validates its type, location, and trace/agent identity. Direct callers may pass `evidence=FailureEvidence(...)`; stores may implement `load_evidence(trace_id)`.
- **Actual agent configuration:** register the current config for the exact alert agent in `agent_configs` or supply `current_config` to `run_critic`. NexusBench currently uses module constants, not an injected runtime config. The DEV adapter snapshots only the existing active `_BASE_SYSTEM`/`_GUESS_SYSTEM`, `MAX_STEPS`, and `TOOL_SPECS`. Runtime replay must consume registered replacement values before applicability can imply operational usefulness. No new runtime knob was invented. Keep the existing validator rule in mind: `MAX_STEPS` is shorter than its 10-character target minimum, and numeric replacement text is also too short; this branch deliberately retains that rule.
- **Shared provenance persistence:** add provenance, validation/applicability flags and rejection reasons to the shared `PatchProposal` contract and SQL schema when that work is authorized. This branch uses a critic-local subclass and an append-only audit sidecar (`CRITIC_AUDIT_PATH`, default `results/critic_dev/proposals.jsonl`). The legacy SQL row does not contain these additional fields. Accepted Kafka payloads do include them.
- **Shared provider metadata:** `services/common/llm_config.py` recognizes only `gemini` and `mock`. The critic's own factory now supports `NEXUS_LLM=ollama` (or `qwen`), with a pinned local Qwen digest; shared provider descriptions should eventually recognize it too. Gemini is refused without verified billing credit, and no paid provider is enabled in this branch.
- **Infrastructure integration tests:** the existing `tests/integration/test_critic_pipeline.py` assumes missing traces can produce stored generic patches and supplies no current config or evidence. Update those fixtures/expectations for the new fail-closed contract when editing that directory is authorized. These infrastructure tests were not run; this task used the fake trace store and unit/e2e suite only.
- **Reporting aggregation:** include `results/critic_dev/c1.json`, `c2.json`, and `c5.json` in the shared results index when authorized. `RESULTS.md` and its generator were left untouched.
